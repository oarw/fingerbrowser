## Design Context

### Users

FingerBrowser is a self-hosted desktop tool for one operator who repeatedly manages multiple isolated browser profiles. The primary jobs are scanning profile state, finding an account quickly, checking proxy and fingerprint context, adding a short operational note, and launching one or several profiles with minimal friction.

### Brand Personality

Professional, restrained, and dependable. The interface should feel like a focused operations console: calm enough for long sessions, dense enough for repeated work, and transparent about kernel and proxy state. It must never feel promotional, gamified, or subscription-driven.

### Aesthetic Direction

Use a light, desktop-first utility layout inspired by the supplied RoxyBrowser references: compact navigation, a strong profile table, efficient toolbars, structured creation forms, and a concise environment summary. Remove all advertising, sales, team, marketplace, AI automation, account-center, and quota surfaces. Prefer cool neutral surfaces, crisp borders, blue for primary commands, green for healthy runtime state, and amber only for actionable warnings. Avoid decorative gradients, oversized cards, glass effects, dark neon styling, and marketing composition.

The brand mark is a cool-white rounded tile containing layered blue browser windows and a green fingerprint. Keep it geometric, recognizable at 16 px, and consistent across the executable, installer, navigation, and brief startup transition.

### Design Principles

1. Put profile identity, runtime state, proxy location, tags, and notes in the main scanning path.
2. Keep primary actions one click away; progressively disclose fingerprint and proxy details when editing.
3. Treat kernel availability as a first-class system state with guided download, install, validation, and manual-path fallback.
4. Use dense unframed sections and tables for operational data; reserve cards for real grouped tools or summaries.
5. Communicate limitations and errors precisely without advertisements, tutorials, or redundant feature descriptions.
