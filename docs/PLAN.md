# FingerBrowser 进度与计划

最后更新:2026-08-18

## 一、总体目标

做一个**自用、无广告、无功能限制**的指纹浏览器管理器,替代 RoxyBrowser。核心能力:多环境隔离、内核级指纹伪装、代理管理和批量运营。

当前路线:**固定并校验开源内核级指纹 Chromium(fingerprint-chromium)+ 自研 Electron 管理器**。管理器提供下载、断点续传、SHA-256 校验、解压和启用;后续是否维护自有 Chromium 补丁栈另行评估。

## 三、已完成明细

### 阶段一 MVP(已交付)
- Electron + Vue 3 + electron-vite 骨架,主/预加载/渲染三进程与 IPC 打通。
- 环境增删改查,分组、标签、搜索。
- 每环境独立 `--user-data-dir` 物理隔离。
- 指纹参数可视化编辑:种子、系统及版本、品牌及版本、CPU 核心数、时区、语言、接受语言、WebRTC 策略;一键"随机种子/全部随机"生成自洽指纹。
- 无认证代理(HTTP/SOCKS5)配置。
- 一键启动/关闭,实时运行状态(圆点指示 + 运行态订阅)。
- 设置:指定托管内核安装目录或手动内核路径(均带选择框)、默认起始页。
- 设置:可选择关闭窗口后驻留系统托盘;退出前检测并提醒仍在运行的指纹环境。
- 本地 JSON 持久化。

### 阶段二 代理与批量(已交付)
- **认证代理 / SOCKS5 本地桥接**:`proxy-chain` 在 127.0.0.1 起匿名代理携带凭据转发,浏览器只连本地端口;随进程生命周期自动起停。
- **按代理 IP 自动填充**:经代理请求 IP 地理接口,自动带出时区/语言/接受语言,保证网络出口与指纹地区自洽。
- **批量启动**:卡片多选,支持"批量启动"。
- **窗口平铺**:按屏幕工作区算网格,给每个窗口传 `--window-position`/`--window-size`,最多两路并发并错峰 250ms 启动。
- 依赖外部化(`externalizeDepsPlugin`),`proxy-chain`/`undici` 正确打进产物(CI 验证通过)。

## 五、暂缓范围

以下能力按当前需求暂不开发:

### 本地 API / CDP 自动化
- 在主进程起一个本地 HTTP 服务(默认 `127.0.0.1:50325`,仅绑本地)。
- 接口:列出环境、启动/关闭环境、返回该环境的 CDP 调试端口(`webSocketDebuggerUrl`)。
- 价值:让外部脚本(Puppeteer/Playwright)能 attach 到指定环境做自动化。
- 关键点:启动内核时加 `--remote-debugging-port=<每环境唯一端口>`,并从 `/json/version` 读取 ws 地址。

- 内置流程编排:打开网址、等待、点击、输入、截图、滚动。
- 通过 3.1 暴露的 CDP 端口驱动;流程可保存、按环境批量执行。
- 可选:录制回放。

### 代理订阅管理
- 集成 Mihomo(Clash Meta)或 Xray-core 内核下载与管理。
- 支持导入订阅链接 / 本地 YAML,节点延迟测速,环境绑定指定节点。
- 参考:Mirage-Browser(Mihomo)、GeekEZBrowser(Xray REALITY/VLESS)。

### 环境备份与云同步
- 本地导出/导入环境配置(不含敏感 Cookie 或可选加密导出)。
- 可选 WebDAV / GitHub 备份。

### 自动更新与跨平台

- 自动更新、macOS 和 Linux 构建当前均不投入。

## 七、后续方向:一致性画像与自研隐私研究

### 7.1 当前取舍

- 继续使用 `fingerprint-chromium` 作为当前生产内核,优先保证下载、校验、安装、启动和环境隔离稳定;不在短期内重写 Chromium 内核。
- 后续自研目标定义为**隐私与环境一致性**:让每个环境对外呈现一套长期稳定、内部互相匹配的设备/地区画像,用于合法的多环境测试、隐私隔离和授权自动化。
- 不以绕过验证码、风控或站点安全策略为验收目标;所有检测和回归只使用自有站点、明确授权的测试环境或公开的指纹诊断页。

### 7.2 开源方案调研结论

- `fingerprint-chromium` 已提供 C++/内核级的种子、操作系统、品牌、CPU、语言、时区、WebRTC 等参数,适合作为 Chromium 路线的基础实现。
- `Camoufox` 的思路是把修改放在浏览器实现层,配合 `BrowserForge` 按真实流量分布生成相关字段;它同时强调随机拼接不一致的 OS、GPU、屏幕和 UA 会产生异常信号,这对我们的画像模型有直接参考价值。
- `Mullvad Browser`/Tor Browser 代表另一条路线:通过统一、可群体化的默认值减少唯一性,适合研究“隐私抗指纹”与“多画像隔离”之间的取舍。
- `puppeteer-extra-plugin-stealth` 可作为自动化检测用的对照样本,但它主要依赖页面脚本层修补,不能替代 Chromium 内核级实现,也不作为生产内核的核心依赖。

### 7.3 画像模型与 IP 联动

1. 为每个环境保存版本化 `profile manifest`:固定种子、浏览器版本、操作系统、设备类型、屏幕、CPU/内存、GPU、字体、语言、时区、WebRTC 和代理绑定,同一环境重启后保持不变。
2. 启动前通过实际代理出口获取 GeoIP 结果,再按国家/地区映射 IANA 时区、主语言、备用语言、`Accept-Language` 顺序和默认地理位置;所有字段写入同一画像并允许用户显式覆盖。
3. 将 UA、UA-CH、`navigator`、请求头、屏幕/窗口、媒体能力、Canvas、Audio、WebGL、字体和 WebRTC 视为相关变量校验,禁止出现明显不可能的组合(例如 Windows UA 搭配 Apple GPU、移动设备搭配桌面窗口)。
4. IP 变更时不静默重写既有环境:提示用户确认并生成新的画像版本,保留旧版本以便回滚和审计。

### 7.4 自研实现顺序

- **阶段 A:画像规范** — 定义字段、来源、依赖关系、版本和迁移规则;增加“画像一致性检查”而不是先增加随机字段。
- **阶段 B:网络与地区** — 完善代理出口探测、GeoIP 缓存、国家到时区/语言映射、DNS/WebRTC 泄漏检查和启动前阻断提示。
- **阶段 C:内核能力** — 盘点现有 Chromium patch 和启动参数,优先补齐 UA/UA-CH、语言、时区、屏幕、媒体能力、Canvas/Audio/字体/WebGL 的同源配置;尽量在 C++/浏览器实现层完成,不依赖可被页面发现的注入脚本。
- **阶段 D:验证矩阵** — 在 CI 运行画像快照、跨重启稳定性、字段相关性和代理出口一致性测试;在授权测试页记录 BrowserLeaks、CreepJS、BrowserScan 等结果,按内核版本建立基线,不把单次评分当作安全承诺。
- **阶段 E:灰度与回滚** — 每项能力用独立开关和 manifest 版本控制,失败自动回退到当前 `fingerprint-chromium` 行为,不影响已存在的环境数据。

## 九、风险与注意

- **内核 GPU 指纹在 Windows 受限**:必要时评估切换/补充内核,或用 `--disable-spoofing=gpu`。
- **反检测是持续对抗**:内核需跟随上游更新;强依赖干净独立代理 IP,单靠指纹不够。
- **合规**:仅用于合法用途(隐私、测试、授权自动化),遵守目标站点条款。
- **私有仓库额度**:继续走"公开跑 CI、跑完私有";文档改动已通过 `paths-ignore` 免触发。
